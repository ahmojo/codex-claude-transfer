# Demo recordings

Animated GIFs that showcase `cct`. The terminal clips are rendered with
[VHS](https://github.com/charmbracelet/vhs); the desktop WebUI clip is recorded
with [Playwright](https://playwright.dev).

| File | Shows |
|------|-------|
| `01-overview.gif` | `cct doctor`, the project-grouped `cct list`, `cct export --all` |
| `02-sync.gif` | Incremental sync: `cct import --merge` (dry-run → real → idempotent re-run) |
| `03-claude-handoff.gif` | Cross-agent handoff: `import --to claude`, then `doctor --tool claude` |
| `04-encryption.gif` | age encryption: `export --encrypt-to` → `inspect --identity` |
| `05-conflicts-remap.gif` | Conflicts: `--replace-with-backup`, `--import-as-copy`, `--map-cwd` |
| `06-export-filters.gif` | Export filters: `--project`, `--session`, `--since` |
| `07-git-handoff.gif` | Git handoff: `export --with-git` → `import --clone` |
| `08-cli-ui.gif` | The interactive terminal wizard, `cct ui` |
| `09-compressed.gif` | Reading compressed `.jsonl.zst` sessions with `zstd` |
| `10-webui.gif` | The desktop WebUI, `cct app` (Doctor, Sessions, Export, Import) |

## Safety

Every clip runs against **fake demo homes** generated by `gen_demo_home.py` —
none of this ever touches a real `~/.codex` or `~/.claude`, so no real prompts,
code, or paths appear on camera. The WebUI clip points `cct app` at a fake
`CODEX_HOME` for the same reason.

## How they're made

- `gen_demo_home.py <base>` — writes fake Codex homes (`laptop/`, `pc/`) with
  realistic sessions across a few projects. `CCT_DEMO_BASE` overrides the project
  path prefix (used to give the WebUI clip natural Windows paths).
- `prep.sh <scenario>` — sets up the state a given tape needs (`base`, `claude`,
  `enc`, `conflict`, `mapcwd`, `git`, `zstd`).
- `*.tape` — VHS scripts (typed commands + timing) for the terminal clips.
- `record.sh` — renders all terminal GIFs in one shot.
- `webui-rec/` — the Playwright project that records `10-webui.gif`.

## Re-recording the terminal clips (VHS)

VHS needs Linux with `ttyd` + `ffmpeg`; on Windows this runs in WSL. `record.sh`
is self-bootstrapping (no sudo): it fetches the headless-Chromium NSS libs
locally, installs `age` if missing, and builds `cct` from source.

```bash
wsl -d Ubuntu -- bash -lc 'bash /mnt/c/Users/faruk/Documents/Codex_sync/demo/record.sh'
# outputs ~/cct-rec/*.gif and copies them here
```

One-time prerequisites (no sudo):
- `vhs`  — `go install github.com/charmbracelet/vhs@latest`
- `ttyd` — static binary from the [ttyd releases](https://github.com/tsl0922/ttyd/releases)
- `ffmpeg` — already present on most distros

## Re-recording the WebUI clip (Playwright)

Runs on Windows, where Chrome has all its libraries.

```powershell
# generate a Windows-path fake home (from WSL, writing to the Windows side)
wsl -d Ubuntu -- bash -lc "CCT_DEMO_BASE='C:\\Users\\you\\projects' python3 demo/gen_demo_home.py /mnt/c/Users/you/cct-webui-demo"

cd demo/webui-rec
npm install
npx playwright install chromium
$env:CCT_HOME = "C:\Users\you\cct-webui-demo\laptop\codex-home"
node record-webui.mjs          # writes out/<hash>.webm
# then convert webm -> gif with ffmpeg (see record.sh for the palette flags)
```
